# 管线选型：为什么这本书不能沿用漫画那套

> 结论先行：**翻译层复用，图像层换掉。**
> 漫画那套（检测气泡 → OCR → 翻译 → 抹字 → 回填）是为「短句 + 白底气泡」设计的，
> 这本书是「双栏密排正文 + 彩色排版」，硬套会把段落切碎、栏序打乱。

---

## ✅ 已定决策（本项目的实际选择）

| 项 |  decision |
|---|---|
| **翻译路线** | **B：EPUB 重排** —— MinerU 解析 → Markdown → LLM 分块翻译 → pandoc 出 EPUB |
| **选择理由** | 技术手册读者要的是内容（结组、保护站、冰川行进），不是原版视觉设计；EPUB 可搜索、可重排字号、便于手机阅读 |
| **放弃的方案** | 路线 A（pdf2zh 双语对照 PDF）：保留版面但双栏串位风险高、且交付物不便携 |
| **OCR 引擎** | **PaddleOCR**（与 A.O.Z 漫画项目一致，精度已在英文印刷体上验证） |
| **仓库命名** | `alpine-skills-zh`（描述性命名，不直接顶书名） |

> 路线 A 仍作为**备选保留**：若后续需要「原版面存档版」，可再用 pdf2zh 跑一次。

---

## 一、这本书的硬约束

| 约束 | 实测值 | 对选型的影响 |
|---|---|---|
| 无文本层 | 抽样 60 页字符数为 0 | 必须 OCR，不能用「抽文本 → 翻译 → 回填」的纯文本路线 |
| 双栏正文 | 是（左栏 + 右栏） | 阅读顺序必须栏感知，否则段落交错 |
| 彩色排版 | 章节编号块、绿/红配色标题、菱形项目符号 | 抹字重排会破坏设计 |
| 全幅照片 | 每页可能有一张跨栏图 | 图注需单独处理，图片不能压字 |
| 页脚面包屑 | `Handbook > Basic Knowledge > ... — 75` | 需照译但页码保留 |
| 分辨率 | 1114×1580 @ 300dpi | OCR 够用（300dpi 是标准下限） |
| 页数 | 357 页 | 规模适中，人工校对可行但需分批 |

## 二、候选方案对比

| 方案 | 定位 | 对扫描件 | 保版面 | 适合本书？ |
|---|---|---|---|---|
| **pdf2zh / PDFMathTranslate** | 版面感知的 PDF 翻译 | 需开 OCR | ✅ 输出双语对照 PDF | **✅ 首选** |
| **BabelDOC** | pdf2zh 的下一代内核 | 同上 | ✅ 更好 | ✅ 备选（pdf2zh 新版常内置） |
| **MinerU** | PDF → Markdown（版面解析） | ✅ 强 | ❌ 输出 MD | ✅ 走 EPUB 路线的首选 |
| **marker** | PDF → Markdown | 一般（偏电子版） | ❌ | ⚠️ 扫描件效果不稳 |
| **docling** | 文档结构解析 | 中等 | ❌ | ⚠️ 表格强、扫描件一般 |
| **Immersive Translate（PDF 模式）** | 商业工具，双语对照 | ✅ | ✅ | ⚠️ 非开源、按量计费 |
| **manga-image-translator** | 漫画管线 | — | 抹字重排 | ❌ 双栏会被切碎 |
| **自己写 OCR + 重排** | 全自主 | ✅ | 看投入 | ❌ 重复造轮子 |

## 三、两条推荐路线

### 路线 A：双语对照 PDF（首选，保留原版面）

```bash
# 装（示例，具体参数以官方 README 为准）
pip install pdf2zh

# 跑（扫描件要开 OCR）
pdf2zh "dokumen.pub_alpine-skills-summer.pdf" -li en -lo zh --ocr
```

产出：原文页 + 译文页对照，或原页上覆盖译文（视版本/参数）。
**优点**：版面、图片、配色全保留，可交付。
**风险**：双栏栏序若识别错，译文会串位 → 所以必须先跑 `scripts/ocr_probe.py` 验证栏序。

### 路线 B：EPUB / Markdown 重排（可读性最好）

```bash
# MinerU 解析（扫描件走 OCR）
pip install magic-pdf[full]
magic-pdf -p "dokumen.pub_alpine-skills-summer.pdf" -o out/mineru
# 得到 markdown → 用 LLM 分块翻译 → 用 pandoc 生成 epub
```

**优点**：可搜索、可重排字号、适合手机阅读；翻译质量最好控制（可整段喂 LLM）。
**代价**：丢掉原书彩色设计与图片版式。

> 对**技术手册**而言，路线 B 的实用性往往高于路线 A —— 读者要的是内容
> （结组、保护站、冰川行进），不是原版的视觉设计。

---

## 四、不建议的路线

**抹字 + 重排回原扫描图**（漫画那套）
- 357 页 × 双栏 × 彩色元素 × 全幅照片
- 中文行宽/字号要逐块适配，工作量远超收益
- 彩色标题块重绘极易失真
- 结论：投入产出比最差

---

## 五、决策闸门（按顺序）

1. **跑 `scripts/ocr_probe.py`** → 看双栏是否被正确分离
   - 栏序正确 → 可以进路线 A
   - 栏序错乱 → 直接走路线 B（或换 pdf2zh 的版面模型），别在检测器上调参
2. **试翻 3-5 页** → 人工看版面可接受度
3. **定术语表** → `glossary/build_dicts.py` 生成字典
4. **分批整本** → 每 20-30 页一批，翻完即校，避免最后一次性返工
5. **校对重点**：术语一致性、页码/面包屑、图注漏译、祈使句语气

---

## 六、待核实项（不要当成定论）

- `pdf2zh` 的 OCR 开关名称与是否内置 BabelDOC，随版本变化较大，
  安装后请以 `pdf2zh --help` 为准。
- `MinerU` 对扫描件的版面还原质量需实测 3-5 页后才能判断。
- 各工具对「彩色标题块」的处理差异较大，建议先用第 100 页
  （含彩色章节号 + 双栏 + 项目符号 + 照片）做统一对比样本。
